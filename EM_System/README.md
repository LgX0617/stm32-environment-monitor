# EM_System

基于 STM32F103 凤凰开发板的山洞边缘服务器环境监测与语音控制系统。

## Directory Layout

- `Core/`: STM32CubeMX generated initialization code. Keep `main.c`, peripheral init files, and CubeMX headers here.
- `BSP/`: Hardware drivers. Put each sensor, display, actuator, and board peripheral in `Inc/` and `Src/`.
- `App/`: Application logic. Put environment data, control rules, alarm logic, display pages, and upper-computer protocol here.
- `Drivers/`: STM32 HAL and CMSIS libraries. Do not edit unless the library version changes.
- `MDK-ARM/`: Keil project and build outputs.

## Adding a Module

1. Add the module header to `BSP/Inc/` and source file to `BSP/Src/`.
2. Add its `.c` file to the `BSP` group in `MDK-ARM/EM_System.uvprojx`.
3. Configure the required peripheral and GPIO in `EM_System.ioc`, then regenerate CubeMX code.
4. Keep threshold decisions and automatic control rules in `App/`, not in the hardware driver.

## Current Placeholder

`BSP/motor.c` provides the fan and pump interfaces. Replace its empty function bodies with TB6612 GPIO control only after the motor pins are generated by CubeMX.
# EM_System STM32 VS Code 开发

本工程目标芯片为 `STM32F103ZE`（Cortex-M3，512 KB Flash，64 KB RAM）。VS Code 配置使用 GNU Arm Embedded Toolchain、OpenOCD 和 Cortex-Debug。

## 工具安装

安装并加入 PATH：

- Arm GNU Toolchain：提供 `arm-none-eabi-gcc`、`arm-none-eabi-objcopy`
- GNU Make（Windows 可使用 MSYS2/MinGW）
- OpenOCD：提供 `openocd`
- VS Code 扩展：`marus25.cortex-debug`、`ms-vscode.cpptools`

连接 CMSIS-DAP 后，在 VS Code 中：

- `Ctrl+Shift+B`：编译，输出位于 `build/`
- 命令面板运行 `Tasks: Run Task` -> `Flash STM32 (CMSIS-DAP)`：编译并烧录
- 在“运行和调试”中选择 `Debug STM32 (CMSIS-DAP)`：启动断点调试

如果工具不在 PATH，可在 VS Code 终端设置环境变量，例如：

```powershell
$env:PATH += ";C:\Program Files\GNU Arm Embedded Toolchain\bin;C:\Program Files\OpenOCD\bin"
```

若使用 J-Link，需要将 `.vscode/launch.json` 的 `servertype` 改为 `jlink`，并配置对应的 J-Link GDB Server。
